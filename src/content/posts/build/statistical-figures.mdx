A mean cannot show whether a sample has two peaks. A regression line cannot show whether one observation controls the fit. A good ranking score cannot tell you whether a predicted probability of 0.8 is credible. Each question needs a different view of the observations.

This guide uses thirty computed figures to connect those questions to graphs. The examples use synthetic data with fixed random seeds: they illustrate how to read a graph rather than report findings about a real population. Replay an animation to follow its construction; the final frame remains available for comparison.

| Question | Start with |
| --- | --- |
| How are individual values distributed? | ECDF, boxplot, beeswarm |
| Is the distribution asymmetric or multimodal? | KDE, violin, raincloud |
| How do two measurements vary together? | Scatter, hexbin, jointplot |
| How uncertain are the supplied estimates? | Interval, forest |
| Does a linear model miss a pattern? | Residual, scale–location, influence |
| Do earlier observations predict later ones? | Lag, ACF, PACF |
| What happens when follow-up ends before an event? | Kaplan–Meier |
| How does a classifier behave across thresholds? | ROC, precision–recall, calibration |

## Distributions

Groups A and B are normal samples with different locations and spreads. Group C mixes two normal components. The same observations appear in several views so that differences come from the representation, rather than from changing the sample.

<StatisticsExamples kind="boxplot" />

Start at the median line, then compare the boxes: each covers the central half of its group's values. Whiskers end at observations within 1.5 interquartile ranges of the box. Isolated points deserve inspection, but that display rule does not establish that an observation is erroneous. A box also hides the gap between C's two clusters.

<StatisticsExamples kind="violin" />

The outline adds distribution shape to a compact group comparison. C's two bulges expose what its boxplot conceals. Each violin here has the same maximum width, so compare its contour rather than treating width as evidence that a group has more observations.

<StatisticsExamples kind="ecdf" />

Choose a value on the horizontal axis and read the fraction of observations at or below it. Every step comes directly from the sample; ties produce a larger jump. Unlike a histogram or smoothed density, this view needs neither a bin width nor a bandwidth. A lower curve at a given value means fewer observations fall below that value.

<StatisticsExamples kind="qq" />

This graph compares A's ordered sample values with quantiles of a normal reference fitted using A's mean and standard deviation. Approximate alignment suggests compatible shape; departures in the ends draw attention to tails. The diagonal is a visual reference, not a confidence band or a formal normality test.

<StatisticsExamples kind="kde" />

A kernel density estimate replaces each observation with a smooth kernel and adds their contributions. Bandwidth controls how much detail survives: a small value can invent distracting bumps, while a large value can merge distinct peaks. The Gaussian kernels used here extend beyond the observed range and do not correct boundaries such as zero for a positive quantity.

<StatisticsExamples kind="beeswarm" />

Each dot retains its observed value on the vertical axis. Its horizontal position only helps nearby dots avoid overlap; it is not a second measurement. This makes small samples and ties visible, although sufficiently dense samples can still overlap.

<StatisticsExamples kind="raincloud" />

Read three layers together: the half density suggests shape, the box summarises the middle, and the dots expose the actual observations. Agreement across those layers is more informative than any one alone. The cloud is still a bandwidth-dependent estimate.

<StatisticsExamples kind="boxen" />

Nested boxes extend the central interval from 50% to 75%, 87.5% and further where sample size permits. They provide more tail detail than one box while keeping groups compact. The smaller sample here supports only a few levels; extra nested intervals would imply more tail resolution than the data warrant.

<StatisticsExamples kind="ridgeline" />

Stacked curves make changes in location and shape easy to scan across groups. All groups share the value axis, but each peak is normalised to the same height. Peak height therefore cannot compare probability density or group size in this implementation.

<StatisticsExamples kind="pp" />

The P–P view compares A's and B's cumulative probabilities at the same observed values. It asks how much probability has accumulated in each sample, whereas a Q–Q plot compares the values associated with matching probabilities. Systematic departure from the diagonal reveals a distributional difference without identifying its cause.

See the [NIST boxplot reference](https://www.itl.nist.gov/div898/handbook/eda/section3/boxplot.htm) and [Seaborn's distribution guide](https://seaborn.pydata.org/tutorial/distributions.html) for the underlying display conventions and smoothing tradeoffs.

## Relationships between variables

<StatisticsExamples kind="scatter" />

Each point is an observed pair. Follow the overall direction, then look for curvature, changes in spread and isolated observations. The optional line is an ordinary least-squares fit with an intercept and one predictor. A line summarises association; it does not establish a causal effect.

<StatisticsExamples kind="hexbin" />

When points overlap, counting them into hexagons exposes where observations concentrate. Darker cells contain more pairs. The fixed grid is computed in data space, so resizing this figure does not change cell counts. A different bin resolution can still change the apparent structure.

<StatisticsExamples kind="density-contour" />

Contours smooth the two-dimensional cloud and connect locations with equal estimated density. These particular lines sit at 15%, 35%, 60% and 85% of the peak density. They do not enclose those percentages of observations and are not confidence regions. Inspect bandwidth choices before interpreting separate islands as separate populations.

<StatisticsExamples kind="pairplot" />

Every off-diagonal panel compares two columns; diagonal panels show each column's histogram. Scanning the matrix helps identify relationships that a single chosen pair would miss. Axes belong to their respective variables, and a visible pairwise pattern need not survive adjustment for another variable.

<StatisticsExamples kind="jointplot" />

The central scatter preserves pairs, while the top and right histograms summarise each variable separately. Marginal peaks tell you where x or y is common. The central cloud tells you which values occur together; the marginal distributions alone cannot recover that pairing.

<StatisticsExamples kind="bland-altman" />

For two methods measuring the same item, plot their difference against their mean. A nonzero average difference suggests a systematic offset; increasing spread suggests that disagreement changes with measurement size. The guides here are the mean difference plus or minus approximately 1.96 sample standard deviations. These are limits of agreement under a normal approximation, not a confidence interval for the mean difference. Whether the disagreement is acceptable requires a separate, practical tolerance. See the [statsmodels agreement-plot reference](https://www.statsmodels.org/stable/generated/statsmodels.graphics.agreement.mean_diff_plot.html).

## Estimates and contingency tables

<StatisticsExamples kind="interval" />

Points locate the three sample means, and bars show supplied normal-approximation 95% intervals. Their widths depend on sample variability and size, not just the differences between means. The component draws the intervals given to it; a different interval method requires different inputs. A 95% confidence procedure describes repeated-sample coverage, rather than a 95% posterior probability for this particular interval.

<StatisticsExamples kind="forest" />

Read each study's estimate and interval against the reference line. Square areas encode supplied weights, and the diamond shows a supplied pooled estimate and interval. This example uses inverse-variance weights under an independent, common-effect normal model. That assumption belongs to the analysis, not to the drawing; the chart does not assess heterogeneity or choose a pooling model.

<StatisticsExamples kind="funnel" />

Standard error increases downward, so more precise estimates appear near the top. The widening guides show the centre plus or minus 1.96 standard errors. Asymmetry can prompt investigation, but variation in study designs, sampling and selective reporting can all matter. A funnel alone cannot establish publication bias; the [Cochrane Handbook](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-13) discusses these interpretation limits.

<StatisticsExamples kind="mosaic" />

Cell area represents a count in a contingency table. Colour reflects the sign and magnitude of the Pearson residual relative to the count expected under independence. Large area means frequent, while strong colour means departure from that expectation; those are different questions. Residual colour is descriptive and does not replace a test with its sampling assumptions checked.

## Regression and time-series diagnostics

The first three views fit the same simple linear regression, including one deliberately unusual observation. Compare their messages before deciding which measurements deserve inspection.

<StatisticsExamples kind="residual" />

A residual is the observed response minus its fitted value. A curved pattern suggests that a straight line misses structure; changing vertical spread suggests that one constant error scale is inadequate. An apparently patternless plot supports further checking rather than proving all model assumptions.

<StatisticsExamples kind="scale-location" />

The vertical coordinate is the square root of the absolute internally standardised residual. This reduces the dominance of large raw residuals when comparing spread across fitted values. A rising or falling envelope points towards changing error variance.

<StatisticsExamples kind="influence" />

Leverage measures how unusual a predictor position is, while the standardised residual measures disagreement with the fitted line. Point area reflects Cook's distance, combining their effect on the fit. The red 4/n threshold is a screening heuristic; investigate a flagged point's provenance and sensitivity before excluding it. The [statsmodels regression diagnostics example](https://www.statsmodels.org/stable/examples/notebooks/generated/regression_diagnostics.html) illustrates related checks.

The next three views share a simulated autoregressive series with coefficient 0.72. Observations depend on their predecessor, so treating them as independent would discard information.

<StatisticsExamples kind="acf" />

The autocorrelation function compares observations separated by each lag. Positive short-lag correlation means nearby values tend to move together. Lag zero is omitted here. Dashed guides are approximate pointwise white-noise references, not universal confidence bands or a simultaneous test across lags.

<StatisticsExamples kind="pacf" />

Partial autocorrelation measures the remaining linear relationship at a lag after accounting for intervening lags. For this first-order process, the population relationship is concentrated at lag one; a finite sample will not give exact zeros elsewhere. This implementation uses the Yule–Walker MLE convention documented in the [statsmodels PACF reference](https://www.statsmodels.org/stable/generated/statsmodels.tsa.stattools.pacf_yw.html).

<StatisticsExamples kind="lag" />

Plot each value against an earlier value to see the actual pairs behind a lag correlation. A diagonal cloud makes dependence visible; curves or separate clusters may reveal structure a single correlation coefficient hides. Both axes share the same value range in this figure.

## Survival and classification

<StatisticsExamples kind="kaplan-meier" />

The curve estimates the proportion remaining event-free over follow-up. It drops at observed events; a censoring mark indicates that an observation leaves follow-up without a known event time. Censoring does not itself cause a drop. The bands use log-log Greenwood intervals and stop at each group's last follow-up. Interpretation relies on suitable censoring assumptions; this example does not model competing risks or delayed entry. See the [lifelines Kaplan–Meier reference](https://lifelines.readthedocs.io/en/latest/fitters/univariate/KaplanMeierFitter.html).

The last three graphs use the same binary labels and predicted scores. They answer distinct questions about ranking, threshold selection and probability accuracy.

<StatisticsExamples kind="roc" />

Moving the decision threshold trades false positives against true positives. Tied scores advance together. ROC AUC summarises ranking across thresholds, but neither selects an operating threshold nor verifies that the scores are calibrated probabilities.

<StatisticsExamples kind="precision-recall" />

Precision asks how many predicted positives are correct; recall asks how many actual positives are recovered. Their tradeoff makes false positive burden visible when positives are scarce. The horizontal baseline is this sample's positive prevalence. The displayed summary is average precision, computed as a step-weighted area rather than trapezoidal interpolation. See [scikit-learn's evaluation guide](https://scikit-learn.org/stable/modules/model_evaluation.html#precision-recall-f-measure-metrics).

<StatisticsExamples kind="calibration" />

Within each score bin, compare the mean predicted probability with the observed positive fraction. Alignment with the diagonal supports probability calibration at that binning resolution. Point sizes expose differing sample counts, empty bins are omitted, and changing the bins can change the impression. A classifier can rank well while being poorly calibrated; the [scikit-learn calibration guide](https://scikit-learn.org/stable/modules/calibration.html) explains the distinction.

## Use the graphs with your own data

Each heading names its reusable `kind`. A post-specific TSX component supplies observations and captions, then MDX imports that component. The drawings compute their geometry from those inputs; the animation does not change the estimates.

```tsx
import { Boxplot, ECDF } from "../../../../components/figures";

const groups = [
  { label: "Before", values: [3, 4, 4, 6, 12] },
  { label: "After", values: [2, 3, 3, 4, 5] },
];

export default function Measurements() {
  return <>
    <ECDF props={{ groups }} caption="Compare the fraction at or below each value." />
    <Boxplot props={{ groups }} caption="Compare the same samples' centre and spread." />
  </>;
}
```

For the component workflow, see [Adding animated figures](/posts/build/animated-figures/). For executable NumPy, pandas, SciPy, Matplotlib and Seaborn examples, see [Edit and run code in the browser](/posts/build/browser-code/). Both approaches keep the observations separate from the choice of graph.
